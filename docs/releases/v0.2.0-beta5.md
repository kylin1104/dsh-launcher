# DSH Launcher v0.2.0-beta5

本版主线是 **MCP 与 Skill 管理**：新增两个视图，可浏览与启停 MCP 服务器、浏览 Skill。变更范围为 `v0.2.0-beta4..v0.2.0-beta5`。

### 中文版

#### ✨ 新增

**MCP 服务器管理**（插件页 → MCP）

- 列出所有 `@deepseek-ai/dsh-mcp-client` 行，按作用范围分为 **DSH 级**（`$DSH_HOME/cordis.patch.yml`，该 DSH 下每个 Profile 都能调用）与 **Profile 级**（某个 Profile 自己的 patch 文件）。
- 每行可**启停**，写回该行所在的层，并由**读回校验**确认；校验失败即报错，不会静默成功。**正在运行的实例会自动生效，无需重启**——dsh 的 patch 层是热加载的（实测：写入后约 10 秒内该服务器进程退出，还原后约 12 秒内重新拉起）。
- 同名服务器按 dsh 的组合顺序判定：**DSH 级覆盖 Profile 级**。被覆盖的行标为「未生效」，并说明这与当前激活的 Profile 无关。
- **添加服务器**：手动填写（名称、行 ID、传输方式、命令/参数/环境变量或 URL、可先建为禁用），或**粘贴 JSON 导入**——兼容通用的 `mcpServers` 结构（JSON 或 YAML，Claude Desktop / Claude Code / Cursor 等工具通用）。导入**先预览再写入**，无法转换的条目会列出原因而不是静默丢弃。
- 一键打开对应层的配置文件；DSH 级配置文件不存在时可一键创建。

**Skill 浏览**（插件页 → Skill）

- 扫描 dsh 会读取的 Skill 目录，按官方 source 与 rank 展示：`自定义目录` → `用户 · DSH 专属` → `用户 · 多 Agent 共享` → `随包内置`。
- 标签同时标出两个正交维度——`项目/用户` 是**作用范围**，`DSH 专属 / 多 Agent 共享` 是**目录归属**：`.dsh` 只有 dsh 读，`~/.agents/skills` 则被多个 Agent 共用。这是两个独立的轴，混为一谈会看不懂层级。
- 项目级目录需要工作区路径，Launcher 没有这个概念，故不列出——界面会说明这一点，而不是显示一个用不上的层。
- 同名 Skill 只保留优先级最高的一个，其余标为「未生效」并可筛选；可查看 `SKILL.md` 内容、打开所在目录。
- **此处不提供启停开关**：dsh 原生没有 Skill 启停机制（frontmatter 的 `disable-model-invocation` 只是阻止模型自动调用）。启停属于 dsh 进程内部行为（插件可通过 `ctx.skills.registerProvider()` 注册低 rank 的 override provider 遮蔽 Skill），外部程序无法代管，故 Launcher 只做只读浏览。

**全局规则**（插件页 → 规则）

- 直接编辑该 DSH 的 `$DSH_HOME/AGENTS.md`：dsh 会把这一份注入该 DSH 下的**每一次会话**，与项目无关，是唯一无需工作区路径就能编辑的用户级配置。此前它只能手工改（虽然已在数据迁移的携带清单里）。
- **点击文件路径**即可用系统默认编辑器打开该文件；文件尚不存在时路径为普通文本、不可点击（此时用页头的「在文件管理器中打开」定位目录）。
- 一并显示**用法/预算**与**单文件上限**（1 MiB），因为超限时 dsh 会**整份忽略**且不报错；保存也据此拒绝——空内容覆盖已有文件同样拒绝（删除文件请用文件管理器）。
- 说明 dsh 的实际语义：它排在所有项目级规则**之前**，预算不足时**最先**被省略。
- **注意规则文件没有文件监视**（与 patch 的热加载不同）：保存提示会如实说明——新会话直接读到新内容，已运行的会话在下次读写文件或恢复会话时刷新。
- 项目级规则由每会话的工作目录决定，启动器没有工作区概念，故不列出，只在界面说明。

**插件总览可下载指定版本**

总览新增「下载」列，列出可获取的版本并安装到插件库。仅当来源可获取（npm / GitHub / store）时提供——本地（`file:`）插件没有 npm 包，不会显示该按钮。

**侧栏范围显示**

MCP / Skill 页侧栏顶部显示**当前激活 DSH**（可切换）与**当前 Profile**（只读），切换 DSH 会重新扫描。要看哪个 Profile 的配置，用右侧的「查看范围」，它默认停在当前 Profile。

「当前 Profile」是持久设置，修改入口集中在 DSH / Profile 页，侧栏只作显示——避免同一状态有两个写入点。

#### 🐛 修复

- **同一行 ID 出现多次时状态会读错、启停会静默无效**：dsh 按行 ID 组合补丁层，**同 ID 以最后一条为准**，且省略的字段**继承**前值（已用 `dsh --dump-config` 实测）。外部工具停用服务器时可能是**追加**一条覆盖行、而非改写原行，于是同一 ID 在文件里出现两次；此前只读/只写**第一条**，导致界面显示与 dsh 实际相反，且点「启用」改的是被覆盖的那条——**看起来成功但毫无效果**。现在按 dsh 的规则取**最后一条**（含字段继承）来读、写、校验；若最后一条**未写** `disabled` 而继承了前面的 `true`，启用时会显式写入 `false`，并对这类行标出「有多条定义」。
- **`setRowDisabled` 会删掉用户显式写的 `disabled: false`**：启用操作此前无条件删掉 `disabled:` 行，改写了本就处于启用状态的行。现在只在值确为 `true` 时才改动；若删掉该行会**继承**到更早的 `true`，则改为显式写入 `false`。
- **下载完成后页面不刷新**：下载会话结束时只推送「进行中」的快照，已完成的会话从不出现在其中，因此「已完成」判断永不命中。新增专门的完成事件通道。
- **切换 DSH 时基本信息面板跳动**：信息表此前按内容自适应列宽，改为固定标签列；`ConfigRow` 也不再按内容收缩。
- **点列表卡片会顺带切换激活项**：DSH 页此前点卡片即切换激活 DSH，浏览列表会连带改动运行目标。现在点卡片只**选中查看**，切换激活走该项「⋯」菜单里的「设为当前」；DSH 页与 Profile 页规则一致。
- **切换 DSH 后右侧不刷新**：MCP / Skill 面板此前只在挂载时扫描一次，切换 DSH 后主进程数据已变而界面仍显示旧内容。现在切换 DSH 会重新扫描。
- **拖拽排序后当前激活项有概率被置顶**：拖拽把手位于行内，在把手上松开鼠标时 `click` 冒泡到行，触发了选中与刷新，而刷新会用服务端顺序覆盖本地乐观排序。现在把手的 `click` 不再冒泡。
- **添加 MCP 服务器时的 YAML 注入（可导致任意代码执行）**：生成的配置行由字符串拼接而成，值有转义、**键没有**，且转义不含换行。构造一个含换行的环境变量**名**即可闭合当前映射并**新开一条完整的 MCP 行**，其 `command` 会被 dsh 直接执行（已复现：写入的文件被解析为两行，注入行出现在扫描结果里，且写回校验照样通过）。现在**所有标量——含键、行 ID、包名——统一走同一条单行转义**。同一处顺带修掉三个配置损坏：`serverName` 含冒号会让整个文件无法解析、含 `#` 会被截断、`url` 含换行会注入行级字段。
- **添加服务器时若填写非法参数形态**（`args` 非数组、`env` 非对象等）会抛内部错误，现在作为输入错误明确拒绝。
- **写入前不校验文档**：dsh 要求补丁文件是顶层数组，否则启动即报错。此前「启用」一个只剩该行的配置会写出**空文件**，而读回校验把它当成成功；现在空文档回落为 `[]`，且写入前统一校验，非法文档一律拒绝。
- **块式 YAML 序列会让解析错位**：`config:` 下的 `- 项` 被误判为「新的一行」，导致该行自己的 `disabled:` 读不到——禁用状态被读成启用、校验确认了这个错误结果、写入时又多加一个 `disabled:` 键（重复键 → 无效 YAML）。现在块的边界按缩进判定，且「本行的键」与「嵌套键」严格区分（`config.opts.disabled` 不再被当作本行状态）。
- **三层解析器对 `disabled` 的判断不一致**（同块内取首、取末、任一为真），同一个文件在不同调用方读出不同结果；现已统一。
- **未加引号/带注释的行 ID 读不到**：`- id: "a"` 会保留引号、`- id: a  # 注` 会整行失配，于是启停会**追加**一条重复行而不是改写原行。
- **`removeRow` 只删最后一块**：用于「整体替换」时会留下更早的块，dsh 仍会应用它，看起来删了其实没删；现在删除该 ID 的**所有**块。
- **启用/停用可能写入无关配置行**：MCP 的启停现在要求**实际生效的块**确实是 MCP 行，否则拒绝；DSH 级启停也拒绝操作不存在的行 ID（此前会追加一条垃圾行到机器级配置）。
- **密钥可能写入日志**：解析失败时记录了 js-yaml 的完整错误信息，其中含**出错源码片段**——对 MCP 配置而言就是 `env:`/`headers:`，即令牌；而日志文件默认按 debug 全量落盘。现在只记录行号。
- **两个插件接口缺少路径校验**：`plugins:readme` / `plugins:reveal` 未做同类接口都有的名称校验，`../..` 可越出插件库读取外部 README、或打开任意目录；现已补上同样的守卫。
- **DSH 页在加载失败后永久转圈**：`refresh()` 在 `dsh.list` 失败时**先 return 后清 loading**，导致侧栏骨架一直转、右侧空白。现在失败路径也会清除加载态，并提示错误。
- **四个错误码没有对应文案**（`dsh.upToDate`、`dsh.notManaged`、`dsh.majorRisk`、`profile.notFound`），提示框会直接显示原始代号；已补齐中英文案。
- **导入 MCP 后改「生效于」不生效**：转换时已把目标范围固化进每条记录，之后改选只改了界面，服务器仍写入**旧范围**；现在改选会清空预览，强制按新范围重新转换。同一弹窗的表单也不再被无关的重渲染清空。
- **被覆盖的 MCP 行仍提供开关**：该行不会生效（DSH 级优先），开关却提示「已禁用/已启用」，属于「看起来成功但毫无效果」。现在这类行列显示原因而非开关；且**任一写入进行中会锁定所有开关**——写入是「读-改-写」，同文件并发会互相覆盖、静默丢失。
- **英文界面混入中文标点**：`、` 与 `（）` 此前硬编码在组件里，现在改为可翻译的 `common.listSep` / `common.qualifier`；读取 Skill 正文时也不再显示「加载可用版本…」。
- **几处失败被静默吞掉**：DSH 健康检查、Profile 的缺失 bundle 提示、DSH 列表加载失败此前不提示，现已各自报错。

#### 🏗️ 工程

- 单元测试 **39 文件 / 511 例**，覆盖 MCP 增删改、Claude 格式转换、Skill 扫描与遮蔽判定、全局规则文件的读写守卫，以及补丁行的多 block 解析、字段继承与嵌套键规则。
- 新增端到端脚本 `scripts/e2e-extensions.cjs`：在真实 Electron 主进程中驱动实际 IPC，断言扫描/启停往返，并在操作前后**逐字节比对**真实 `cordis.patch.yml`，确保测试不污染用户配置。
- 修复 `store-overview.ts` 中一个**裸 NUL 字节**（模板字符串里），它使该文件对所有文本工具呈现为二进制。
- 补丁文件改为**原子写**（临时文件 + rename，旧内容留作 `.bak`）：此前直接覆写，进程中断或磁盘占满会留下截断的 `cordis.patch.yml`，dsh 将无法启动。

### English

The headline of this release is **MCP and Skill management**: two new views to browse and toggle MCP servers, and to browse skills. Range: `v0.2.0-beta4..v0.2.0-beta5`.

#### ✨ Added

**MCP server management** (Plugins → MCP)

- Lists every `@deepseek-ai/dsh-mcp-client` row, split by scope: **DSH level** (`$DSH_HOME/cordis.patch.yml` — callable from every profile under that DSH) and **Profile level** (a profile's own patch file).
- Each row can be **enabled/disabled**, written back into the layer it came from and confirmed by a read-back; a failed verification is an error, never a silent success. **A running instance picks the change up automatically — no restart** — because dsh hot-reloads its patch layers (measured: the server's process exits within ~10s, and comes back within ~12s).
- Duplicate server names resolve by dsh's composition order: **the DSH level overrides the profile level**. An overridden row is marked inactive, and the tooltip states that this is unrelated to which profile is currently active.
- **Add a server**: fill it in by hand (name, row id, transport, command/args/env or URL, optionally created disabled), or **paste JSON to import** — compatible with the common `mcpServers` shape (JSON or YAML, shared by Claude Desktop / Claude Code / Cursor and others). An import is **previewed before it is written**, and anything that cannot be converted is listed with a reason instead of being dropped silently.
- One click opens the config file for the scope in view; a missing DSH-level file can be created in place.

**Skill browsing** (Plugins → Skill)

- Scans the skill directories dsh reads, labelled by dsh's own source and rank: `custom dirs` → `user · DSH-only` → `user · multi-agent` → `bundled`.
- Each label names both orthogonal dimensions — `project`/`user` is the **scope**, `DSH-only` / `multi-agent` is **who owns the directory**: only dsh reads `.dsh`, whereas `~/.agents/skills` is shared by several agents. They are independent axes; conflating them makes the hierarchy unreadable.
- Project-level directories need a workspace path, which the Launcher has no notion of, so they are not listed — the UI says so rather than showing a layer that never applies.
- A duplicate name keeps only the highest-precedence one; the rest are marked inactive and can be filtered for. View a `SKILL.md` body, or open its folder.
- **No toggle here**: dsh has no native skill switch (the frontmatter `disable-model-invocation` only stops automatic model invocation). Toggling a skill is behaviour inside the dsh process — a plugin can register a lower-rank override provider through `ctx.skills.registerProvider()` — which an external tool cannot drive, so the Launcher stays read-only.

**Global rules** (Plugins → Rules)

- Edits this DSH's `$DSH_HOME/AGENTS.md` directly: dsh injects that one file into **every session** under the DSH, regardless of project, making it the only user-level config editable without a workspace path. It was previously hand-edit only (despite already being carried by data migration).
- **Clicking the file path** opens it in the OS default editor; while the file does not exist the path is plain, unclickable text (use the header's "show in file manager" to locate the folder instead).
- Reports **usage against the budget** and the **per-file cap** (1 MiB), because dsh ignores an oversized file ENTIRELY and silently; saving is refused on that basis, and an empty save over an existing file is refused too (delete it from the file manager instead).
- States what dsh actually does: this file precedes every project-level rule, and is the FIRST to be dropped when the byte budget runs short.
- **Rules have no file watcher** (unlike the hot-reloaded patch layers); the save toast says so — new sessions read the new content, and a running session picks it up on its next file read/write or on resume.
- Project-level rules come from each session's working directory, which the launcher has no notion of, so they are described rather than listed.

**Download a specific plugin version**

The overview gained a "download" column that lists the available versions and installs one into the plugin library. It appears only when a source can actually be fetched (npm / GitHub / store) — a local (`file:`) plugin has no npm package, so no button is offered.

**Scope display in the rail**

The MCP / Skill rail shows the **active DSH** (switchable) and the **current profile** (read-only); switching the DSH re-scans. To look at a different profile's config, use the pane's "Viewing" control, which opens on the current profile.

"Current profile" is a persisted setting, and the places that change it are the DSH and Profile pages. The rail only reports it, so the same state never has two writers.

#### 🐛 Fixes

- **A row id that appears more than once was read wrong and toggled to no effect**: dsh composes patch layers by row id, so the **LAST** block for an id wins and a field it omits is **inherited** (measured with `dsh --dump-config`). An external tool may disable a server by **appending** an override row instead of editing the original, leaving two blocks for one id; the Launcher read and wrote only the **first**, so the UI showed the opposite of dsh's state and clicking "enable" edited the overridden block — **reporting success while changing nothing**. It now resolves, writes and verifies the **last** block (inheritance included), writes an explicit `false` when that block states nothing but inherits `true`, and flags such rows as "multiple rows".
- **`setRowDisabled` deleted an explicit `disabled: false`**: enabling a row unconditionally removed the `disabled:` line, rewriting rows that were already enabled. It now only touches a value that is actually `true`, and writes an explicit `false` when deleting the line would inherit an earlier `true`.
- **The page never refreshed after a download finished**: only an in-flight snapshot was pushed, so a completed session never appeared in it and the "done" check could never match. A dedicated completion channel was added.
- **The basic-info panel shifted when switching DSH**: the table sized its columns to the content; it now has a fixed label column, and `ConfigRow` no longer shrinks to fit.
- **Clicking a list card also switched the active entry**: on the DSH page a click used to activate that DSH, so merely browsing changed the run target. A click now only **selects it for viewing**, and switching what is active is the "set as current" action in the entry's "⋯" menu. The DSH and Profile pages follow the same rule.
- **The right pane did not refresh after switching DSH**: the MCP / Skill pane scanned only on mount, so after switching DSH the main process had new data while the UI still showed the previous DSH's contents. Switching the DSH now re-scans.
- **The active entry could jump to the top after reordering**: the drag handle sits inside the row, so releasing a drag on it let the `click` bubble to the row, which selected it and refreshed the list — and that refresh overwrote the local optimistic order with the server's. The handle's click no longer bubbles.
- **YAML injection when adding an MCP server (leading to arbitrary code execution)**: a generated row was assembled by string interpolation — values were escaped but mapping **keys were not**, and the escaping did not cover newlines. A crafted environment-variable **name** containing a newline closed the current mapping and opened a **second, fully valid MCP row**, whose `command` dsh would then execute (reproduced: the written file parsed as two rows, the injected row appeared in the scan, and the write-back verification still passed). Every scalar — keys, row id and package name included — now goes through one single-line escaper. The same pass fixes three corruptions: a colon in `serverName` made the whole file unparsable, a `#` truncated the value, and a newline in `url` injected a row-level field.
- **Malformed add-server input** (`args` not an array, `env` not an object, …) raised an internal error instead of being rejected as invalid input.
- **Writes were not validated as documents**: dsh requires a top-level array and fails loud at boot otherwise. Enabling a row that was the file's only row used to write an **empty file**, and the read-back counted that as success; an empty document now falls back to `[]`, and every write is validated first.
- **A block-style YAML sequence misaligned the parse**: a `- item` under `config:` was read as "the next row", hiding the row's own `disabled:` — a disabled server read as enabled, verification confirmed that wrong state, and writing added a second `disabled:` key (a duplicate key, i.e. invalid YAML). Block boundaries are now indent-aware, and a row's own keys are distinguished from nested ones (`config.opts.disabled` is no longer read as the row's state).
- **Three parsers disagreed about `disabled`** (first-in-block, last-in-block, any-true), so one file read differently per caller; they now share one rule.
- **Quoted or annotated row ids were invisible**: `- id: "a"` kept its quotes and `- id: a  # note` failed to match, so a toggle **appended** a duplicate row instead of editing the original.
- **`removeRow` removed only the last block**: used as a wholesale replace it left an earlier block behind, which dsh still applied — the row looked removed but was not. It now removes **every** block for the id.
- **A toggle could write into an unrelated config row**: enabling/disabling an MCP row now requires the **effective** block to be the MCP row, and the DSH-level toggle refuses an id that is not present (it used to append a junk row to the machine-wide config).
- **Secrets could reach the log**: a parse failure logged js-yaml's full message, which embeds an excerpt of the offending SOURCE — for an MCP block that is `env:`/`headers:`, i.e. tokens — and the file sink captures debug by default. Only the line number is logged now.
- **Two plugin handlers skipped path validation**: `plugins:readme` / `plugins:reveal` lacked the name guard every sibling applies, so `../..` could read a README from outside the store, or open an arbitrary folder.
- **The DSH page span forever after a load failure**: `refresh()` early-returned on a failed `dsh.list` BEFORE clearing `loading`, leaving the rail's skeleton spinning and the detail pane blank. The failure path now clears it and reports the error.
- **Four error codes had no text** (`dsh.upToDate`, `dsh.notManaged`, `dsh.majorRisk`, `profile.notFound`), so toasts displayed the raw code; both languages now define them.
- **Changing "applies to" after an MCP import did nothing**: the target scope was baked into each converted entry, so the picker changed while the servers were still written to the **old** scope. Changing it now clears the preview and forces a re-convert, and the form is no longer wiped by unrelated re-renders.
- **An overridden MCP row still offered a switch**: that row never takes effect (the DSH level wins) yet the switch reported "disabled/enabled" — a control that silently does nothing. Such rows now state the reason instead, and **every switch locks while any write is in flight**: the write is read-modify-write, so concurrent toggles in one file overwrote each other and silently lost an edit.
- **CJK punctuation leaked into the English UI**: `、` and `（）` were hardcoded in components; they are now translated (`common.listSep` / `common.qualifier`). Reading a skill body no longer says "Loading available versions…".
- **Several failures were swallowed silently** (the DSH health check, the profile's missing-bundle warning, a failed DSH list load); each now reports.
